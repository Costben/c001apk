# 长文模板规范

这个规范描述一份「长动态 / 长文」的排版，用于把写好的稿子原样搬进客户端发布。
写好的文档可以直接导入 App：**草稿箱 → 右上角「导入模板」**，解析后可以「存到草稿箱」或「去发布」。

实现：`data/LongPostTemplate.kt`（解析与校验）、`ui/drafts/TemplateImportScreen.kt`（导入界面）。

## 文件格式

UTF-8 纯文本，`.md` / `.txt` 均可。也可以在 App 里直接粘贴文本。

## 头部（可选）

文件以一行 `---` 开头，到下一行 `---` 结束。字段都是 `key: value`，`#` 开头是注释。

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `title` | 一行文本 | 标题。会作为正文首行，后面空一行接正文 |
| `visibility` | `public` / `self` | 可见范围，默认 `public`（也认 `所有人` / `仅自己`） |
| `topics` | 逗号、顿号或分号分隔 | 话题。发布时追加在正文末尾，写成 `#话题#` |

不认识的字段不会静默丢掉，导入时会提示「不认识的字段 xxx，已忽略」。

头部可以整段省略。省略时，正文第一行的 `# 标题` 会被当成标题。

## 正文

空行分段，原样保留。

因为动态是纯文本（不渲染 Markdown），解析时会做两件事：

- 标题行和小标题的 `#` / `##` 标记去掉，只留文字
- 图片从正文里摘出来，按出现顺序进图集

其它 Markdown 语法不做转换，写什么发什么。

## 图片

```markdown
![说明](来源)
```

- 来源一般写 `http(s)` 链接：导入时下载到缓存，读不到的那张会跳过并提示，不影响其余内容
- 也可以写本机路径（`/sdcard/Pictures/a.jpg`，`file://` 前缀会被去掉），但应用没有存储读取
  权限，受分区存储限制，大多数系统目录下的文件读不到；需要本机图片时，导入后在发布框里用
  图片选择器补上更稳妥
- 按出现顺序进图集，**最多 9 张**

## 长度

正文（含标题行和话题行）上限 **2000 字**，超过时导入界面会把字数标红并禁用两个按钮。

> 服务端其实能收更长的正文（实测 1832 字的动态发布成功），2000 是本客户端输入框的上限；更长的稿子请自行分段发布。

## 完整示例

```markdown
---
title: 一加 Ace 7 上手体验
visibility: public
topics: 一加Ace7, 开箱
---
拿到手第一感觉是轻，边框的过渡比上一代更干净。

![正面](https://example.com/front.jpg)

## 屏幕

亮度够用，户外也能看清，调光没有明显的频闪感。

![屏幕](https://example.com/screen.jpg)

## 总结

这一代值得换，尤其是从两年前那台升上来的。
```

导入后，这条动态的正文是：

```
一加 Ace 7 上手体验

拿到手第一感觉是轻，边框的过渡比上一代更干净。

屏幕

亮度够用，户外也能看清，调光没有明显的频闪感。

总结

这一代值得换，尤其是从两年前那台升上来的。

#一加Ace7# #开箱#
```

图集是两张：`front.jpg`、`screen.jpg`。
